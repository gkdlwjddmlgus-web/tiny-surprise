# Tiny Surprise

모바일 세로 화면용 생일 서프라이즈. 브라우저 제목과 첫 화면은 **Tiny Survey**입니다.

## 실행

Python 3.12를 권장합니다. 이 폴더에서 실행하세요.

```sh
python -m pip install -r requirements.txt
streamlit run app.py
```

모바일에서 같은 네트워크의 컴퓨터 IP와 포트로 접속하거나 Community Cloud에 배포합니다.

## Streamlit Community Cloud

1. 이 폴더의 내용(`app.py`, `.streamlit`, `frontend`, `config`, `static`, `requirements.txt`)을 GitHub `tiny-surprise` 저장소 루트에 올립니다.
2. Streamlit Community Cloud에서 저장소와 브랜치를 선택하고 Main file path를 `app.py`로 지정합니다.
3. Python 3.12로 배포합니다. 별도 비밀키나 API는 필요 없습니다.

이 작업에서 GitHub 업로드 및 실제 Cloud 배포는 수행하지 않았습니다.

## 설정

`config/birthday.json`만 수정하면 이름, 애칭, 3개 질문/선택지, 편지, 문구, 이미지, 재생 시간을 변경할 수 있습니다. 시간 단위는 밀리초입니다. JSON은 유효한 문법으로 유지하고 질문은 3개를 유지하세요.

- `letter_char_ms`: 한 글자 출력 간격
- `letter_pause_ms`: 문장 사이 간격
- `timing`: 분석, 뽑기, 가짜 광고, 카운트다운 간격
- `assets`: `static/` 기준 상대 경로
- 축하 문구의 `{name}`, `{nickname}`은 자동 치환됩니다.

편지는 임시로 작성한 기본 문구입니다. 선물하기 전에 개인 메시지로 바꿔 주세요. **공개 GitHub 저장소에 올리면 개인 편지와 이름도 공개됩니다.** 비공개 저장소라도 방문자는 브라우저로 전달된 설정을 읽을 수 있으므로 비밀 정보를 넣지 마세요.

첨부된 GIF 7개는 업로드 순서대로 의미 있는 이름으로 복사했으며 원본 바이트와 애니메이션을 보존했습니다. PNG는 제공되지 않았습니다. 추후 `static/assets/ditto.png`를 넣고 `assets.ditto`를 `assets/ditto.png`로 바꾸면 친구 모음에 나타납니다. 이미지 오류는 하트 대체 그래픽으로 처리합니다.

## 구현 선택

설치된 Streamlit 1.63.0의 `st.html(..., unsafe_allow_javascript=True)` API를 확인하고 실행을 시도했습니다. 이 환경의 실제 브라우저에서 HTML만 표시되고 초기화 스크립트가 실행되지 않아, 공식 `st.iframe`의 HTML 문자열 입력으로 전환했습니다. 1.63.0을 고정해 이 동작을 재현할 수 있게 했습니다. 구버전 legacy `components.v1.html`은 사용하지 않습니다.

iframe은 화면 전체 크기로 표시되며 HTML/CSS/Vanilla JS가 상태와 타이머를 소유합니다. Python 위젯이나 rerun에 의존하는 장면 전환은 없습니다. 리로드 시 처음부터 시작하며 서버 저장은 없습니다. Streamlit의 개발 파일 감지로 코드가 바뀌면 앱이 재실행될 수 있습니다.

공식 static serving은 `.streamlit/config.toml`의 `server.enableStaticServing=true`로 활성화합니다. 이미지 URL은 `app/static/assets/...`이며 로컬에서 HTTP 200 / `image/gif` 응답을 확인했습니다. 외부 CDN, 웹 폰트, 광고, 분석 코드, API 호출은 없습니다. 피날레 음악은 아래 BGM 설정을 참고하세요. Streamlit 자체 사용량 통계도 비활성화했습니다.

## 파일

- `app.py`: Streamlit 진입점, JSON 로딩, iframe 구성
- `frontend/app.js`: 이벤트 기반 상태 머신과 타이머 정리, 편지, 다시 보기
- `frontend/style.css`: 모바일 레이아웃, 가챠 머신, 등장/파티 효과
- `config/birthday.json`: 사용자 설정
- `static/assets/`: 원본 GIF
- `QA.md`: 실제 검증 결과와 한계

편지는 한 장의 종이 안에서 문단별로 타이핑되며, 이미 표시한 문단과 서명은 계속 DOM에 남습니다. 종이 내부에서 위아래로 스크롤해 다시 읽을 수 있습니다. 맨 아래를 읽는 동안만 자동으로 아래를 따라가고, 위로 스크롤하면 자동 따라가기를 멈춥니다. 다시 맨 아래로 내려오면 재개합니다.

`지금 문장 완성` / `다음 문단` 버튼으로 진행할 수 있습니다. 종이의 빈 영역 탭도 같은 동작을 하지만, 기존 문단의 텍스트 터치나 스와이프는 진행 입력으로 사용하지 않습니다. 450ms 연속 입력 방지와 자동 타이머 정리를 유지합니다. `편지 전체 보기`를 눌러도 이미 표시된 문단 노드를 교체하지 않고 나머지를 추가합니다. 완료 버튼은 서명 아래, 종이 내부 맨 끝에 나타납니다.

편지·봉투·서명·보상·안내 문구에는 하트를 사용하지 않습니다. 우주 오프닝과 별빛, 종이 질감, 글로우는 유지합니다. OS 동작 줄이기 설정에서는 CSS 애니메이션과 타이핑 지연을 줄이고 폭죽은 생략합니다. 원본 GIF 자체의 움직임은 계속 재생됩니다.

## 수동 확인

시작 → 세 질문 → 결과 뽑기 → 꽝 → 포기하기 만류 확인 → 광고 → 편지 터치/전체 보기 → 추가 기회 → 다시 뽑기 → 당첨 카운트다운 → 피날레 순으로 진행합니다. 피날레의 세 버튼을 각각 확인하세요. Safari와 실제 휴대폰에서는 주소 표시줄 변화, 노치 safe-area, 긴 편지 스크롤을 한 번 더 확인하는 것을 권장합니다.


## Cinematic Letter v2

`config/birthday.json`의 `cinematic`에서 오프닝을, `letter_lines`에서 편지를 관리합니다. 기존 설문/가챠/피날레와 원본 GIF는 유지합니다. 기본 원문은 나뇽이가 규령에게 쓴 12문단입니다. 마지막 항목은 서명으로 표시됩니다.

- `opening_lines`: 태초 → 빛 → 존재 → 바로 → 너! 순서의 5문장
- `blackout_ms`, `opening_durations_ms`(첫 3문장), `pause_before_you_ms`, `you_ms`: 오프닝 타이밍
- `envelope_ms`: 봉투 등장·개봉·편지지 상승 시간
- `signature_pause_ms`, `reward_delay_ms`: 서명 전 대기 및 서명 후 보상 대기
- `enable_stars`, `enable_envelope`: 별빛/봉투 연출 사용 여부
- `letter_char_ms`, `letter_pause_ms`: 글자 및 문단 출력 간격

기본값은 암전 0.7초, 첫 세 문장 2.6/3.2/2.8초, ‘바로’ 표시 후 정적 1.2초, ‘너!’ 1.8초, 봉투 2.5초입니다. 편지가 시작되기까지 약 14.8초이며, 12문단 자동 재생은 서명과 보상 대기까지 약 24.7초입니다(전체 약 39.5초). 탭이나 전체 보기로 단축할 수 있습니다. 브라우저가 백그라운드 탭의 타이머를 제한하면 더 길어질 수 있습니다.

편지 재열람은 우주 오프닝을 생략하고 봉투부터 시작합니다. 첫 편지 완료 시 `선물 받으러 가기 🎁`는 두 번째 뽑기로, 재열람 완료 시 버튼은 피날레로 이동합니다. 보상은 별도의 누적 카운터 없이 기존 상태 전환으로 한 번만 처리합니다.

회귀 테스트는 앱 의존성 추가 없이 Node 내장 테스트 러너로 실행합니다.

```sh
node --test tests/cinematic.test.cjs
```

이 테스트는 가상 DOM과 가상 시간을 이용한 컨트롤러 테스트입니다. 실제 모바일 화면의 레이아웃 검증과 별개이며 결과는 `QA.md`에 구분해 기록합니다. Streamlit 배포에는 Node가 필요하지 않습니다.


## 누적 편지 및 피날레 폭죽

축하 메시지는 `celebration_message`(첫 문장)와 `celebration_message_extra`(강조할 두 번째 문장)에서 설정합니다. 두 문장은 별도 p 요소로 렌더링되어 항상 줄을 구분합니다. 기존 설정 파일에 두 번째 속성이 없으면 첫 문장만 표시합니다.

피날레 폭죽은 Canvas 2D와 requestAnimationFrame으로 약 5.5초 동안 8발을 발사합니다. 마지막 3발은 짧은 간격으로 발사합니다. DPR은 최대 2, 동시 입자는 최대 180개이며 외부 의존성은 없습니다. 두 번째 당첨 후 피날레 진입과 `축하 다시 보기`에만 재생합니다. 재생 중 연속 클릭은 무시하고, 종료 후 재생은 새 Canvas/루프로 시작합니다. 편지로 이동하거나 장면을 나가면 Canvas와 이벤트·루프를 정리합니다. 백그라운드에서는 루프를 멈추고 복귀 시 이어 재생합니다.

새 스크롤/입력/폭죽 테스트도 `node --test tests/cinematic.test.cjs`로 실행합니다. 실기기 검증 범위와 한계는 QA.md를 참고하세요.

## 피날레 BGM

사용자가 main에 업로드한 `static/audio/birthday.mp3`를 그대로 사용합니다. 현재 파일은 3,955,968바이트이며 브라우저에서 확인한 길이는 123.624초입니다. 별도의 다운로드 음원이나 시험용 음원을 포함하지 않습니다.

Python이 음원을 읽을 수 있으면 파일 내용의 SHA-256 앞 16자리를 버전으로 계산합니다. 재생 URL은 `app/static/audio/birthday.mp3?v=<버전>`이므로 같은 파일명으로 새 음악을 올려도 이전 캐시와 구분됩니다. 파일이 없거나 비어 있거나 읽을 수 없으면 무음으로 계속 실행합니다. 디코딩/재생 오류도 앱 흐름을 막지 않습니다.

두 번째 뽑기의 직접 클릭/터치에서 단일 오디오 요소를 무음으로 준비합니다. 피날레 진입 및 `축하 다시 보기`에서는 처음부터 재생합니다. 기본 volume은 0.4이며 **무한 반복하지 않고 곡이 끝나면 정지**합니다. 실제 체감 음량은 기기/브라우저 설정에도 영향을 받습니다.

자동 재생이 차단되면 `🎵 음악 재생하기`를 눌러 시작할 수 있습니다. 재생 중에는 `⏸ 음악 일시정지`로 바뀝니다. 일시정지는 재생 위치를 보존하며 다시 재생하면 이어집니다. 곡이 끝난 뒤 재생 버튼을 누르거나 축하 다시 보기를 누르면 0초부터 시작합니다. 축하 다시 보기는 일시정지 상태에서도 새로 재생을 시도합니다. 폭죽 재생 도중 연속 다시 보기 클릭은 기존 정책대로 무시합니다.

피날레 이탈, 페이지 이동, 백그라운드 전환에서는 정지·음소거하고 재생 위치를 초기화합니다. 하나의 HTMLAudioElement만 사용하며 별도 재생 루프/타이머/AudioContext를 추가하지 않습니다. 이전 재생 Promise도 무효화해 다른 화면에서 소리가 나지 않게 합니다.

모바일 자동 재생은 기기 정책에 따라 차단될 수 있으므로 수동 재생 버튼을 유지합니다. [WebKit 사용자 제스처 안내](https://webkit.org/blog/6784/new-video-policies-for-ios/)를 참고하세요. 실제 iOS Safari/Android Chrome 기기의 정책·체감 음량은 별도 확인이 필요합니다.

오디오 서버 설정 테스트와 클라이언트 회귀 테스트는 각각 아래 명령으로 실행합니다. 앱 배포 의존성에는 추가 패키지가 필요 없습니다.

```sh
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/cinematic.test.cjs
```


## 광고 및 편지 음악

추후 아래 두 파일을 main에 추가하면 해당 구간 음악이 활성화됩니다. 아직 포함되어 있지 않으며 누락/빈 파일/읽기 실패 시 그 구간만 무음으로 진행합니다. 디코딩 실패도 장면 전환을 중단하지 않으며 다른 곡 재생에는 영향을 주지 않습니다.

| 경로 | 구간 | 기본 음량 | 반복 |
|---|---|---|---|
| `static/audio/ad_intro.mp3` | 광고 보기 클릭 → 우주 오프닝 | 35% | 없음 |
| `static/audio/letter_bgm.mp3` | 너! → 봉투 → 편지 재독/완료 버튼 | 35% | 있음 |
| `static/audio/birthday.mp3` | 마지막 생일 피날레 | 40% | 없음 |

파일마다 내용 해시를 계산해 교체 후 캐시를 구분합니다. 하나의 HTMLAudioElement만 재사용하며 곡 전환 시 이전 곡을 먼저 정지하므로 동시 재생하지 않습니다.

광고 보기 클릭에서 광고 음악을 시작합니다. 광고 파일만 없는 경우에는 편지 음악을 같은 직접 제스처에서 무음으로 준비합니다. 정책상 자동 재생이 거절되면 해당 구간에 `🎵 음악 재생하기`가 나타나며 직접 눌러 시작할 수 있습니다. 브라우저의 정책을 강제로 해제하지 않습니다.

존재 문장 종료 300ms 전에 광고 음악을 250ms 동안 fade-out하고 완전히 정지합니다. ‘바로’를 표시할 때도 한 번 더 강제 정지·음소거하며 재생 컨트롤은 숨깁니다. ‘바로’ 이후 1.2초 동안 새 음악이나 효과음을 만들지 않고, ‘너!’에서 편지 음악으로 전환합니다. 요청한 간격에 맞춰 기존 ‘바로’ 등장 0.8초 + 대기 1.2초를 합산하던 부분만 총 1.2초로 변경했으며, 나머지 오프닝 문장/봉투 타이밍은 유지합니다.

편지 음악은 봉투와 본문 렌더링 때 재시작하지 않습니다. 문단 자동 출력이 끝난 뒤에도 사용자가 이전 내용을 읽을 수 있도록 유지하고, 완료 버튼으로 재뽑기에 이동할 때 250ms fade-out합니다. 편지 다시 읽기는 기존처럼 오프닝을 생략하고 편지 음악부터 시작합니다. 오프닝을 건너뛰는 경우에도 편지 음악으로 즉시 전환합니다.

음악 일시정지는 현재 구간에서 재생 위치를 유지합니다. 별도의 `🔇 음소거`는 모든 곡에 적용되며 장면 전환과 피날레 다시 보기에서도 유지됩니다. ‘소리 켜기’로 해제할 수 있고, 자연 종료된 곡을 음소거 버튼만으로 다시 시작하지 않습니다. ‘바로’ 구간에서는 컨트롤로 정적을 깨뜨릴 수 없습니다.
